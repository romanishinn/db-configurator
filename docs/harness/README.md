# Харнесс D&B: как мы работаем

Общие правила, память, проверки, бюджет и роли для всех сессий. Источник схемы — пост про харнесс (правила 1–8), перенесённый на наш проект.

## Одно общее пространство (память)
| Что | Файл | Зачем |
|---|---|---|
| Страница старта | `docs/STATE.md` | единственное, что читает новая сессия и сессия после сжатия (хук `tools/harness/session-start.sh`) |
| Журнал решений владельца | `docs/decisions.md` | цитаты целиком, по направлениям |
| Видение | `docs/vision.md` | образ результата важнее технических требований |
| Записки передачи дел | `docs/handoff/` | пишутся до 80% контекста и проверяются следующей сессией |
| Ретро | `docs/retro/` | раз в неделю, начинается с таблицы «сделано / не сделано» |

Если хук не сработал и страницы в контексте нет, сессия обязана сказать об этом первой строкой и не продолжать.

## Оркестр
Оркестратор — главная сессия (она читает навык `/task`). Субагенты работают по узким заданиям; сами они вопросов владельцу не задают и друг друга не вызывают.

| Роль | Файл | Делает | Модель | Пишет код |
|---|---|---|---|---|
| Оркестратор | главная сессия + навык `task` | цикл, вопросы, апрув, сбор результатов | основная | нет |
| Планировщик | `planner` | план, готовое вместо велосипеда, «готово» по путям, риски | opus | нет |
| Инженер БД | `db-engineer` | миграции, RLS, права, Storage, тесты доступа | sonnet | да |
| Инженер движка | `engine-engineer` | расчёт цен, импорт каталога, эталонные тесты | sonnet | да |
| Инженер интерфейса | `frontend-engineer` | конфигуратор, CRM, страницы, КП, проверка в браузере | sonnet | да |
| Автор текстов | `copywriter` | DE/EN/HR тексты без выдуманных фактов | sonnet | тексты |
| Проверяющий | `qa-verifier` | тесты, красные линии, сценарии, уровень «готово» | sonnet | нет |
| Ревьюер | `reviewer` | независимый взгляд, максимум 2 круга | opus (другая модель) | нет |
| Летописец | `scribe` | decisions, STATE, хвосты, записки | sonnet | только docs |

Навыки: `task` (цикл), `office-hours` (вопросы с вариантами), `handoff`, `retro`.

## Цикл задачи
`/task <что сделать>` → вопросы (office-hours) → план (planner) → **апрув владельца** → сборка по ролям → проверка (qa-verifier) → ревью (reviewer, ≤2 круга) → запись (scribe) → отчёт до 5 пунктов.
Подробно: `.claude/skills/task/SKILL.md`.

## Правила харнесса (схема из поста → наш проект)
1. **Журнал решений.** Цитата целиком, иначе «например» станет законом. → `decisions.md`, `scribe`.
2. **Видение.** Агентам важнее знать образ результата, технику предлагают они. → `vision.md`.
3. **Одна страница на старте.** Не весь архив. → `STATE.md` + хук.
4. **Бюджет на задачу.** Подписку скриптом не измерить, поэтому бюджет в шагах: ≤8 запусков агентов, ≤2 круга ревью, ≤2 попытки починки CI; выход за бюджет не более чем на четверть, если это доводит до результата.
5. **Записка до 80% контекста**, следующая сессия её проверяет. → навык `handoff`.
6. **Ревью другой моделью**, максимум два круга; не сошлось — менять подход. → `reviewer` (opus; исполнители sonnet).
7. **«Не получается» только после проверки:** что проверил, что узнал, что гипотеза. Сначала ищем готовое, потом строим своё.
8. **«Готово» = работает в проде по всем путям** (лестница уровней ниже).

## «Готово»: лестница уровней
1. **Реализовано** — код и зелёные тесты.
2. **Проверено на стенде.**
3. **Проверено на своём аккаунте на проде.**
4. **Работает в проде для всех.**
Для D&B «все пути» = клиентский интерфейс · CRM · КП (немецкий и английский) · работа без БД · правила доступа в SQL. Если сайт или боевая БД из среды недоступны, это «не проверено», а не «ок».

## Красные линии (проверяются скриптом)
`sh tools/harness/redlines.sh` и в CI: секреты; запрещённые имена (список вне репозитория: секрет `REDLINE_TERMS` или локальный `.redlines.local`); закупочные/маржинальные ключи в `data/` и миграциях; файлы, которые нельзя коммитить (записки с экономикой, PDF/Excel, `.env`).
Остальные правила — в `CLAUDE.md` (производитель, хостинг, БД, цены, движок, ASSUMPTION).

## Выкатка и полномочия
Ветка → PR → CI → ревью. После апрува подхода сессия вливает сама то, что прошло ревью и проверки, и потом сообщает. Только со слова владельца: необратимое (удаление данных, миграция на боевую БД, платные сервисы, письма реальным людям, обещания клиентам). Новое идёт стенд → свой аккаунт → все. Секреты не печатаются.

## Пробелы в навыках: что соберём
| Пробел | Что нужно | От кого |
|---|---|---|
| Дизайн-стандарт `docs/design.md` | референсы (скрины) с пояснением, что именно нравится и что не переносить; потом оформим стили и скилл | владелец |
| Тексты КП и лендинга на DE/EN | факты (сроки, гарантия, производитель) и носитель языка для финального чтения | владелец |
| Сверка чисел со страницами каталога | доступ к PDF каталога (путь `SW_PDF_DIR`) в среде агента | владелец |
| Автотесты страниц (Playwright) | перенести сценарии, которые мы гоняли вручную, в репозиторий и CI | `frontend-engineer` |
| Проверка прода | доступ к опубликованному сайту и боевой БД из среды агента (сейчас закрыт) | настройка сети окружения |
| Независимое ревью другим вендором | сейчас другая модель того же вендора; при желании подключить сторонний ревьюер | владелец |
| Расход лимитов | скрипт, снимающий расход подписки, пока невозможен: бюджет в шагах | — |
| Список запрещённых имён | завести секрет `REDLINE_TERMS` | владелец |
